## 事情的起因

一切来自于对 AI 深深的恐惧和对未来的迷茫。

我是一位二进制漏洞研究员。今年的五月份，我使用 agent 加上 Ghidra MCP，轻易地就挖掘到了 IoT 设备中的漏洞，并在自己的设备上成功利用。那一刻，我觉得我和我的岗位都要被 AI 所替代了。

我陷入了深深的迷茫和不安中，一个想法在我脑海中形成：

> 与其被动地让 AI 替代我，我不如主动构建一个工具，先把我自己替代了。

模型会越来越强，与之对应的，大模型厂商的 harness 和 agent 也会越来越完善。跟模型比推理、跟大模型厂商比 harness 的安全工具，迟早会被下一版 agent 取代。所以我做了一个不推理、不下判断的 MCP 工具：[Treasure Map](https://github.com/JoeyZzZzZz/treasure-map)。

## 第一次尝试

说干就干。我结合漏洞研究时的流程，有了一个想法：把固件抽象成一本书，每一页都是一个二进制程序，将这本书交给 AI 来阅读，AI 能告诉我哪里有未修补的漏洞、固件里用了什么加密算法等等。

具体的步骤如下：

1. 全量扫描固件解包后的文件系统，找出里面所有的二进制程序。
2. 利用 Ghidra 全量逆向每一个二进制，将伪代码、AI 生成的函数概要以及函数的调用关系保存在数据库当中。
3. 由 AI 读取数据库，概括每个二进制及对应函数的功能，并列出可能存在的漏洞以及对应的伪代码。每个二进制以及函数都保存为一个 Markdown 文档。
4. 通过 Obsidian，将全量的文档封装为一个仓库，利用反向链接保存函数和二进制之间的调用关系。打开后可以像书一样阅读每个二进制的功能和可能存在的漏洞，并能通过关系图谱查看调用关系图。
5. 构建一个对话 agent，查询数据库中对应的数据并回答提问。

我花了不到一个月的时间做出来了。当 agent 回答了一堆可能存在的漏洞，并在 Obsidian 中列出了满满的分析结果时，我很兴奋。但这种兴奋立马就被现实给浇灭了，是的，几乎都是误报。

我在逐个复核过程中发现，几乎都是看起来有问题，但不是输入被过滤，就是入口不可达，以及大量的幻觉。这绝不是我想要的，我再次陷入了迷茫中。

## 反思后的重试

我反思了之前设计不合理的地方：

1. 建立在不准确的判断之上，任何结论一定是不可信的。
2. 事实数据只有是或否，没有诚实的未知选项。
3. 这么大量的数据，给人看的知识库除了满足虚荣心，似乎没有其他用处。
4. 大模型厂商做出的 agent 越来越好用，应该站在巨人的肩膀上。

于是我转变了设计思路，开始做一个面向 agent 的 MCP，Treasure Map 诞生了。

一开始我的思路还是把固件做成一本书的形式，按照危险度进行排序，排名越高的越有可能是真漏洞。但很快我就发现，排名高的几乎都是误报，真正的漏洞则被埋在了一堆未知里，agent 根本无法找到。因为要保证数据真实，就必然有很多的未知；当未知过多时，也便无从排序了。

在修改了很多版都无法解决这个问题的时候，项目的名称再一次提醒了我。对啊！**这是一张地图，而不是一本书。**

书是一维线性的，有唯一的目录顺序，AI 按顺序从第一页读到最后一页。地图是多维的，没有内在顺序：测绘员看等高线，司机看路网，军官看制高点，水文学家看河流……同一张图，各自选各自的视角。

于是就设计了多个视角过滤候选，让 agent 自行选择要看的视角：是按漏洞调用的可达性？还是按参数是否可控？抑或是否有过滤等等。既然 AI 已经足够聪明，那就让它自己决定吧。

当然，实现下来，很多数据确实没办法直接获取到，很多视角也都是未知状态，候选过多的情况并没有好转。

## 灵光乍现时

正当我苦恼于如何降低候选数量时，思绪突然回到了小时候。我想起了我以前最爱看的书《冒险小虎队》，让我记忆犹新的是里面的解密卡：放在书本上，按照对应的角度，就能解出谜题。

等等，解密卡放在书本上，既不会影响原有的内容，又能够获得新的内容，那不就是我想要的、能过滤候选的东西吗？

于是，覆盖在底图之上的标注层诞生了。AI 会把自己的判断结果通过分析写入到这一层，那些无法获取的数据也能通过推理拿到了；同时还能将 AI 的判断积累起来，即使更换了 agent 也能复用。两层的数据也完全隔离，标注层的修改绝不影响只读的事实层。

## 最后一块拼图

虽然有了标注层，确实能过滤掉很多无用的噪音，但数量庞大的候选仍然是一个严峻的问题。Agent 不可能完全遍历所有的候选并都给出结论，这不现实且成本极高。

于是我想到了之前复现 1day 时经常用到的方法——补丁对比。当我把两幅固件地图进行对比时，agent 只需要关注变化的部分，就能轻易地找出修补了哪些漏洞。并且由于保留了危险调用的过滤和可达性等信息，还可以检测补丁是否完整修补了漏洞、有没有绕过的可能。这极大地提高了可用性，最后一块拼图也找到了。

> 我本想造一个替代自己的工具，最后造出来的，是一个让我比以前更强的工具。
